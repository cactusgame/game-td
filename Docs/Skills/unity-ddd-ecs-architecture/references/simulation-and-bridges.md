# ECS 模拟、并行与 Unity 桥接

## 状态所有权

修改系统前列出相关状态的权威存储、写入者、读取者及写入阶段，例如：

| 状态 | 权威拥有者 | 写入边界 | 读取者 |
| --- | --- | --- | --- |
| 当前生命 | Battle 的 ECS Health | 伤害归并/受控初始化与恢复阶段 | 死亡判断、战斗快照 |
| 建筑等级与投资 | Facilities 对象模型 | 建造/升级用例提交 | 属性生成、经济退款 |
| 当前位置 | ECS 位置组件 | 移动/受控传送与恢复阶段 | 空间索引、表现快照 |
| 金币 | Economy 账户 | 消费/奖励用例提交 | UI、建造预览 |

这只是示例，生命也可以属于普通对象实现。选定权威后，不同时维护 `Unit.Health`、`HealthComponent` 和 MonoBehaviour 生命作为多个可写真值。

定义、实例状态、只读快照分离：配置给出基础属性，运行组件保存当前生命和冷却，表现快照提供读取结果。索引、渲染插值和 UI 缓存允许复制派生数据，但必须能从权威状态重建。

## 规则与写入

- 热路径优先使用适合 Burst 的非托管组件、只读定义与纯函数。是否采用 Jobs/Burst 根据批量规模、调度和同步成本决定。
- DamageRules 计算伤害，DamageResolutionSystem 在确定顺序下归并并写入生命；不能让动画、投射物脚本与多个 Job 各自随意扣血。
- 统一能力组件可服务英雄、怪物、塔和墙段；特殊规则通过领域规则、标签或数据策略表达，不复制全部生命周期。
- 纯规则不执行 IO、不取全局时间或随机源、不调用托管服务。将模拟时间、随机状态和必要上下文显式提供给规则。
- 避免每单位托管对象、DI 作用域、热路径 LINQ 分配和接口回调。非热路径合理使用对象与接口。
- Baking 或运行时加载可将内容验证后转成运行定义、Blob 或 Native 数据，不要求所有内容都走同一种管线。共享定义只读，原生资源有明确释放者。

## 时间与系统顺序

会话拥有 World，明确一个模拟驱动。采用自动 PlayerLoop 或手动推进中的一种，防止同一 World 重复推进。编辑器退出、读档、对局结束都需停止输入并释放拥有的资源。

用固定步/模拟时钟表达战斗时序。明确暂停、倍速、追赶上限与积压处理策略；渲染插值不改变真实位置或命中判断。固定步本身不能保证跨平台确定性。

可参考的阶段链，需按实际玩法调整：

```text
接收/校验命令 -> 受控提交 -> 意图/AI -> 移动与空间同步
-> 寻敌/攻击 -> 命中收集 -> 伤害归并 -> 死亡/破坏
-> 必要业务后果 -> 胜负判断 -> 一致快照 -> 表现
```

明确空间查询读取移动前还是移动后的位置，投射物和近战如何共享命中语义。使用系统组及更新顺序约束表达逻辑顺序，不能依赖文件顺序。系统顺序与 Job 完成顺序分别检查，前者不会自动替代后者。

## Jobs、结构变化与同步

- 声明读写集合、依赖与并行划分；同一目标被多个来源命中时，先收集请求，再按业务要求受控归并。
- 并行容器和 ECB 的并行写入 API 必须按对应版本规则使用；不能无保护并行追加同一 DynamicBuffer 或修改同一生命值。
- 若结果依赖顺序，定义稳定排序键与裁决规则，例如 tick、目标 ID、来源 ID、攻击序号。线程完成顺序和 chunk 顺序不能作为玩法规则。
- 创建、销毁、增删组件等结构变化在明确阶段直接批量执行或通过 ECB 延迟执行，说明何时 playback、何时可观察新实体及如何处理失败。
- ECB 负责记录并回放 ECS 操作，不提供账户、地图与 ECS 之间的业务原子性，也不能假定失败会自动回滚已回放操作。
- 在读取主线程结果、销毁 World、保存快照等必要边界完成相关 Job；避免逐实体 Complete，遵守 Native 容器生命周期。
- enableable component 可减少某些结构变化，但不是所有状态机的固定实现。使用前验证当前包支持与查询语义。

## 桥接与表现

```text
输入/网络入口 -> 公开命令 -> Application/模拟命令入口
-> ECS 系统与规则 -> 结果/一致快照 -> Unity 视图、动画、HUD
```

公开业务契约使用稳定 ID、意图和结果，不把 EntityManager、可变组件引用或 Native 容器所有权交给 UI。内部专用渲染系统可以直接读 ECS，但需限定只读职责和同步规则。

表现可以读取最新快照做插值并消费一次性反馈；玩法事实与音效/粒子通知区分。反馈丢失不能造成少发奖励、漏掉死亡或无法重建视图。

用领域 ID 关联实例与视图，Entity 句柄仅在当前 World 范围使用。实体死亡后先完成或可靠记录必要后果，再回收；死亡动画可继续播放，其视图不再拥有可攻击或阻挡真值。

## 性能结论

ECS 主要改善数据组织与批量模拟；SpriteRenderer、动画、血条、透明叠加、CPU/GPU 同步可能仍是瓶颈。以目标设备、预计峰值和实际预算测量模拟、桥接、渲染、GC 与原生内存。不要用 Editor FPS 或“已用 ECS”承诺万单位性能。
