# 一致性、完整用例与验证

## 命令、查询与事件

| 通信 | 含义 | 示例与要求 |
| --- | --- | --- |
| 命令 | 请求执行行为 | BuildTower；校验权限、阶段、资源与版本 |
| 结果 | 可观察的执行状态 | 成功、失败及原因；异步时用 CommandId 关联 |
| 查询 | 读取当前或指定版本状态 | 建造预览、金币、单位快照；不改权威状态 |
| 领域事件 | 已提交的领域事实 | TowerBuilt、UnitDied；用过去式命名 |
| 集成事件 | 面向其他上下文的公开事实 | 转换为稳定契约，不泄露内部实体布局 |

队列接收成功不表示业务成功。排队命令至少说明接收与执行结果的区别、取消与过期规则。重复请求在有重试或重复投递的边界具备去重依据。

同一用例必须立即满足的不变量通过受控提交维护；可延迟后果才能使用最终一致性，并定义重试、去重、失败记录与恢复方式。UI/统计通知通常可异步；扣费与生成建筑不能靠独立事件订阅恰好成功。

不要默认事件溯源。存档快照、运行时领域事件、跨模块可靠待办与表现反馈各有用途，不能混为一种消息总线。

## 建塔：跨对象与 ECS 的完整路径

不变量：资源不足不建塔；建塔失败不永久扣款；成功后设施、占地与战斗能力一致；一个命令不能生成两座塔。

1. 输入转换为 BuildTowerCommand，携带定义 ID、位置及必要的请求身份。
2. 预览只计算可建性；正式执行在稳定模拟边界重新检查阶段、世界/地图版本、占地、资源与内容定义。
3. 应用协调器准备受控变更：资源预留、占地预留、设施创建、ECS 注册。预留需要明确释放和失败恢复。
4. 按实现能力选择预分配后无失败提交、可回滚变更集，或显式 Pending 状态机。主线程执行本身不等于事务；Pending 对象在完成前不能攻击、阻挡或被查询为成功建筑。
5. 所有必要部分成功后完成扣费与激活，记录完成结果，再发布 TowerBuilt。失败时撤销本次预留和部分创建；不可立即回滚的后果必须进入可恢复待办，不能静默半成功。
6. 表现依据已提交状态创建视图。视图创建失败可以重建，不回退核心玩法或重复扣费。

这些步骤是语义要求，不要求实现通用事务框架。简单模块可在同步受控入口内完成，复杂跨帧流程才需要状态机。

## 伤害与死亡：ECS 内部及跨模块后果

1. 命中阶段输出伤害请求，携带必要身份、tick 和结算数据。
2. 归并阶段采用明确的同时结算或顺序结算语义，执行伤害规则、更新生命并判断死亡。明确是否允许同 tick 反击、护盾先后与溢出策略。
3. 死亡标记或等价受控状态确保只提交一次；死亡后禁止继续攻击与移动，具体时点由玩法约定。
4. 如果死亡影响阻挡、建筑生命周期、任务或胜负，在明确边界提交这些后果，或持久保留带事实 ID 的待处理记录。关键后果未处理时不能销毁其唯一数据。
5. 奖励去重与死亡事实关联；领域 ID 和死亡事实 ID 不应因对象池复用而混淆。
6. 最后输出快照与反馈，按规则回收 ECS 实体。表现侧播放死亡动画不再次裁决死亡。

## 存档、恢复与会话隔离

- 仅在一致边界捕获快照，必要时完成相关 Job 和受控结构变化。记录快照覆盖的 tick、格式/内容版本及范围。
- 保存必要权威状态：账户、设施、战斗、任务、波次、模拟时间、随机流、命令与未完成关键后果。不是每个游戏都需要保存每项，但不能遗漏恢复所依赖的状态。
- 使用稳定 ID 建立保存关系；恢复后重建 ID 到 Entity、视图和索引的映射，不能复用旧 World 的 Entity Index/Version。
- 明确恢复方式：构造新 World 并切换，或受控原地恢复。旧命令、订阅、Native 数据与异步任务均需清理或失效。
- 导航、加载、网络响应等携带会话代次与相关版本；读档/重启后拒绝旧结果，避免写入新世界。
- 随机按用途分流，保存玩法所需状态；种子相同、固定步和单机可复现并不证明跨平台逐帧确定性。
- 局内回滚与局外永久进度区分，永久奖励按事实去重；不要因重放死亡消息或恢复历史快照重复发奖。
- 快照重建表现；不靠重放历史粒子、音效或动画事件恢复真实状态。

## 验证与评审

依据变更选择必要验证，避免对文档修改运行整套无关游戏测试：

| 风险 | 验证重点 |
| --- | --- |
| 规则变更 | 数值边界、无效输入、不变量、溢出与可复现性 |
| 跨模块提交 | 资源不足、占地变化、出生失败、重复命令、取消、回滚 |
| 并行战斗 | 多源命中同目标、同时致死、稳定结算、死亡去重 |
| 系统时序 | 暂停、倍速、追赶、目标失效、结构变化可见时点 |
| 生命周期 | 重复进入/退出、双驱动、Native 释放、旧回调失效 |
| 存档恢复 | 一致快照、ID 重建、随机流、待办恢复、奖励去重 |
| 桥接表现 | 快照延迟、插值、视图丢失重建、动画不影响玩法 |
| 性能 | 目标设备峰值下 CPU/GPU、同步、GC、原生内存 |

通过公开行为、正式端口和只读快照断言结果。规则可做独立测试，系统需验证真实执行顺序；不要只测试纯函数就宣称并行与生命周期正确。

评审交付给出“触发入口 -> 应用协调 -> 状态写入 -> 后果提交 -> 表现读取”的实际路径，并说明本次验证覆盖哪些环节。未执行的编译、运行或设备测试应如实标注。
