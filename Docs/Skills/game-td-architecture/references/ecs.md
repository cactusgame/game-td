# DDD 与 ECS 运行规范

## 状态与规则

DDD 的实体身份、领域语义与一致性要求不等于必须使用富对象实现。ECS Entity 是世界内技术句柄，不等于持久化领域身份。

| 内容 | 推荐实现 |
| --- | --- |
| 大量单位生命、位置、冷却、效果、行动状态 | 非托管 ECS 组件 |
| 移动、目标筛选、攻击、命中、效果推进 | 批量系统，适合时使用 Burst/Jobs |
| 伤害、叠加、距离等规则 | 可测试、可供 Burst 使用的纯函数 |
| 账户、玩家档案、出战方案、编组、墙拓扑 | 普通 C# 模型，按实际需求演进 |
| HUD、Sprite、Animator | 快照驱动的表现 |

明确每种组件的写入系统与允许时点。系统共同维护一个领域对象的业务约束，不把每个组件当成一个 DDD 聚合。
公共 Health/Armor/Faction 等能力可服务单位、设施与墙段。特殊规则仍归相关领域，不做万能 UnitBase。
多态策略在热路径可解析成枚举、标签或只读数据；避免每单位托管对象、接口调度、LINQ 分配和全局回调。
JSON/ScriptableObject 属于创作与加载侧，验证后转成只读数值、Native 数据或 Blob，运行时不修改共享定义资产。

## 世界、调度与并行

- 对局拥有 World；桥接器绑定明确 World，不默认到处查 `DefaultGameObjectInjectionWorld`。
- 当前原型：`BattleEntryPoint.Tick -> BattleSession.Advance -> EcsBattleSimulation.Step -> BattleSystemGroup.Update`。若改成 Unity 自动驱动，移除旧驱动并验证不会双重推进。
- VContainer 管会话级托管服务。World、Native 容器、输入订阅按作用域清理，不能只依赖 Editor 自动回收。
- 固定步累加要有追赶上限；明确超时如何丢弃时间或降速。暂停、恢复、冷却、延迟攻击基于模拟时钟。
- 系统顺序可以是：提交命令 -> 必要空间同步 -> 意图/AI -> 移动 -> 寻敌/攻击 -> 命中/伤害 -> 死亡/破坏 -> 奖励/目标/胜负 -> 输出快照。
- 显式表达 UpdateAfter/UpdateBefore 或分组，不依赖类名、文件顺序、订阅顺序。
- Job 输入声明只读/可写与依赖；同目标多源写入采用请求收集及归并，不能无保护并行追加同一 Buffer 或累加英雄血量。
- 结构变化通过受控 EntityCommandBuffer 或明确提交阶段完成；ECB 本身不等于跨资源/地图的业务事务。
- 只在需要结果的边界完成 Job，避免每实体 Complete。主线程同步、快照复制和结构变化都需计入性能分析。

## 接触原型的语义与替换

当前约定是进入接触时双方各结算一次 `max(0, attack-defense)`；持续重叠不重复，分离后允许重击。
双方按接触处理前的属性结算，致死仍允许同次反击，生命最低 0，死亡后不能移动或攻击。
圆形检测使用实际地面半径，必要时扫掠相对运动；绘图高度和 Sprite 大小不参与碰撞。
当前仅英雄对怪物为 O(N)，不做怪物两两扫描；无物理推挤是原型选择，不是长期规则。
若需求改成持续攻击、冷却、阵营混战或推挤，应显式调整模型与测试。不能保留旧接触标记造成意外行为。
保持检测可替换；在实际数据下比较自研几何、空间分区和引擎查询。不预先宣称某方案最高效。
死亡只提交一次；后续奖励、目标与破口先完成或记录待处理状态，之后再回收实体。死亡动画可以继续显示但不保持可攻击/阻挡真值。

## 桥接与持久化

- 输入 -> MoveIntent/命令 -> 模拟；模拟 -> 批量结果/只读快照 -> 表现。
- 公开契约不暴露 EntityManager 或可变组件引用。不要为 UI 每帧逐实体调用托管仓储。
- 保存稳定 ID 与必要状态；恢复后建立 ID 到 Entity 的映射。Entity 的 Index/Version 不能作为跨 World 持久 ID。
- 异步导航、加载等结果携带会话代次/相关版本，恢复后拒绝旧结果。
- 快照在一致边界捕获，覆盖资源、设施、墙拓扑、生命、技能、命令、波次、有效规则、随机流及必要待处理任务。
- 不靠重播历史音效事件恢复，不重复发放永久奖励；表现从快照重建。
- AI/战斗随机与纯表现随机分流。种子、固定步和测试内复现不意味着跨平台/跨版本逐帧确定性。

## 性能与测试

ECS 优化 CPU 数据处理不自动解决 2D 渲染、透明叠加、动画、材质、血条或 GPU 瓶颈。
SpriteRenderer 可作为首版适配，但规模扩大时需要测量渲染、同步和对象数量；不要仅把 MonoBehaviour 改成 Entity 就承诺万单位性能。
性能 HUD 的缺失采样显示 n/a；Editor 内存含编辑器开销，Unity allocated/reserved/managed 不等于 OS 工作集。
用目标设备和预计峰值测试，区分模拟耗时、快照同步、渲染提交、GPU、GC 和原生内存。
验证接触去重、同步致死、失效目标、极端数值溢出、出生失败、边界、随机恢复与重复启动销毁。
