# 战斗建设

## 玩家入口

打开 `Assets/Scenes/Development/DefensePlayground.unity` 或地图编辑器的试玩，进入 Play。按 **B** 或点击“建设模式”进入，战斗继续推进，WASD 仍可移动英雄；士兵的 R、数字键和技能快捷操作在建设模式中暂停读取。退出时恢复。

- 点击空地，固定该 Tile 为建筑左下角锚点，弹出建设菜单。菜单校验完整占地、出口、金币和单位净空；不可建项直接置灰并说明原因，城门和敌台不出现在空地菜单。选择建筑后在原位显示完整占地，移动鼠标不会改变位置；点击菜单“确认建设”完成。建筑占地宽高固定读取配置，兵营统一从下方出兵。右键/Esc 取消后可重新选地块。射程圈和营门净空圈不算建筑占地。
- 每次建设、升级或售卖成功后自动退出建设模式，恢复普通战斗输入；失败则保留当前选择，不扣费，允许重试。再次建设需按B进入。
- 点击已有建筑查看升级分支、费用和属性增量。主堡可升级，不能售卖。互斥路线不能同时选择，不能降级。当前配置使用即时建设和升级，导出器拒绝非零工期，避免界面承诺尚未实现的计时施工。
- 点击售卖后再次确认，整座建筑移除并释放占地。退款为 `向下取整(本局实际投资 × 退款率 × 当前生命比例)`；地图预放不虚构基础建设投资。已支付升级计入投资，已毁建筑不能售卖；兵营售卖同时撤离所属士兵。
- 城墙：选起点、终点，预览费用和冲突，点击菜单确认，成功后返回普通战斗模式。吸附网格交点和已有节点；建成的墙不提供移动、旋转功能。
- 城门：只在城墙菜单提供。点击墙的位置固定为门的定位参考，选择门框和门洞规格，在原位沿墙吸附后通过菜单确认。门的方向继承墙，鼠标移动不改变位置。售卖城门移除整个区间并留下缺口，不退回普通墙。
- 敌台：只在城墙菜单提供，在点击的墙节点或墙身位置原位预览、确认；墙中部的原墙在同一笔提交中切成两条，城门身份和余墙投资保留。敌台目前使用独立建筑生命及箭楼攻击能力，素材未配置时复用箭楼；没有新增登城、驻军系统。售卖敌台需先显式售卖相连墙段，避免连带删除。
- 售卖墙：支持整段及沿墙整数区间。红色高亮表示实际删除范围，确认后留下缺口。不能截断半座城门；余墙必须满足城门端部净空。原墙投资按保留长度分配，移除投资只退款一次。剩余方向不变。

## 配置源与分类

`Config/GameContent.xlsx` 的“建筑”表新增两个字段：

| 字段 | 值 | 含义 |
| --- | --- | --- |
| category | PlayerBuildable | 玩家可在战斗中建设；是否可售卖仍由 canDemolish 决定 |
| category | Decoration | 地图装饰，不创建战斗建筑，不允许玩家建设、升级、售卖；物理阻挡仍服从空间配置 |
| category | BuiltIn | 地图内置功能建筑，不允许玩家新建或售卖；可配置升级，当前主堡属于这一类 |
| placementKind | Building / Wall / Gate / Bastion | 普通矩形建筑、连线城墙、嵌墙城门、墙上敌台 |

市集、水井、教堂、农庄、民居、瓦砾已归 Decoration；主堡归 BuiltIn；箭楼、法师塔、炮坊、兵营及工事归 PlayerBuildable。分类不以建筑名字或 UI 隐藏按钮裁决，正式建设入口再次校验。

城墙费用按沿墙 Tile 长度向上取整计价；城门目前按座计价。墙与门的实际尺寸仍分别来自共享工事定义和沿墙整数区间，不使用建筑表中的矩形尺寸生成墙几何。普通建筑与敌台的占地读取建筑表。既有法师塔、炮坊的战斗能力仍服从原攻击配置，不由分类自动添加功能。

运行 `Tools/ContentConfiguration/export_config.py` 同步生成 JSON。`construction-content.json` 保存分类、费用、退款和升级；`facilities.json` 投影空间和战斗基础能力，装饰的 hasFunction=false，敌台的 wallMounted=true。源表是唯一内容维护入口。

## 状态与阅读路径

1. `Tools/MapPlaytest/Unity/Views/BattleConstructionView.cs`：输入状态、上下文菜单、确认与取消；`ConstructionPreviewView.cs` 只绘制网格和幽灵。
2. `Tools/MapPlaytest/Application/Sessions/MapPlaySession.Construction.cs`：权限、预览、升级和售卖；`MapPlaySession.Fortifications.cs`：墙、门、敌台和局部拆墙。
3. `Gameplay/Construction/Application/Sessions/MapConstructionState.cs`：隔离布置候选与空间校验。已有地图空间和独立 WallNetwork 聚合仍为权威来源，候选校验不修改源地图。
4. `Gameplay/Construction/Domain/Aggregates/BuildingDevelopment/BuildingDevelopment.cs` 保存本局投资和普通建筑升级选择；兵营编制与升级资格继续由 BarracksRoster 拥有。生命周期协调暂沿用现有 MapPlaySession，不新增第七个业务领域。
5. `Gameplay/Battle/Simulation/Bridges/EcsBattleSimulation.cs` 持有建筑生命和战斗能力；升级同步保留生命比例与攻击冷却，装饰不创建战斗实体。售卖兵营通过 ISoldierDismissal 撤军。

正式操作在模拟步之间执行：检查阶段、分类、金币、空间和单位净空 → 创建隔离候选 → 同步模拟空间和建筑 → 发布新布置 → 结算扣款或退款 → 刷新表现。空间同步失败恢复旧布置，不支付；表现不裁决建设结果。重启清空投资、升级和本局新增设施。

## 验证

`BattleConstructionTests` 覆盖分类与入口限制、只读预览、配置固定的多格占地、资金不足、兵营下方出口、升级互斥及主堡升级、退款去重、兵营撤军、门框完整拆除、余墙投资、敌台节点和墙中部切分。配置导出测试覆盖非法分类与装饰攻击配置。

当前仍沿用项目已有的保守导航投影；本次没有改变墙轮廓的导航精度。动态画面与运行截图只代表已检查的开发场景，不代表所有分辨率和素材套装均已验收。
